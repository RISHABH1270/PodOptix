02 Architecture

Component Architecture

PodOptix is a single Go binary with clearly separated layers: HTTP handlers → store → database, with a side-channel background scheduler for metric collection.

Internal component architecture and dependencies
📐Component Responsibilities
🔷 API Layer
HTTP routing, JWT validation, request parsing, response serialization. Each entity has its own handler file. No business logic — delegates to store.
🗃️ Store Layer
All SQL lives here. Each function maps to exactly one query. Returns Go structs. Never talks to Prometheus — only the DB.
📊 Collector
Prometheus HTTP API client. Runs P95 PromQL queries over the cluster's lookback window. Produces raw metric structs for the Analyzer.
⏰ Scheduler
24-hour background ticker. Iterates all connected clusters, fires a goroutine per cluster (bounded concurrency), updates last_synced_at on completion.
🔐 Auth
JWT HS256 issuance and validation. AES-256-GCM for Prometheus token encryption. Single responsibility — no HTTP layer coupling.
📦 Models
Shared Go structs (Cluster, Recommendation). json tags control API shape. Sensitive fields tagged json:"-" to prevent leakage.

Startup sequence: EnsureDatabase → SyncSchema → New (pool init) → Ping. If any step fails, the server exits immediately — fail fast.
FunctionDescription

go · internal/store/store.go 
type Store struct {
    pool *pgxpool.Pool // heap-allocated pool, shared by all operations
}

func New(databaseURL string) (*Store, error) {
    config, err := pgxpool.ParseConfig(databaseURL)
    if err != nil {
        return nil, fmt.Errorf("parse db url: %w", err)
    }

    config.MaxConns        = 10
    config.MinConns        = 2
    config.MaxConnLifetime = time.Hour
    config.MaxConnIdleTime = 30 * time.Minute

    pool, err := pgxpool.NewWithConfig(context.Background(), config)
    if err != nil {
        return nil, fmt.Errorf("create pool: %w", err)
    }

    s := &Store{pool: pool}
    if err := s.Ping(context.Background()); err != nil {
        return nil, fmt.Errorf("ping db: %w", err)
    }
    return s, nil
}

07 Core Workflows

Key Business Flows

The three critical paths in PodOptix — cluster registration, background sync, and manual recalculation.

📊Prometheus Query Strategy
✅
Why P95? P99 would over-provision; P50 would under-provision. P95 × 1.2 safety buffer catches burst traffic while eliminating idle waste.
promql 
-- CPU P95 per container (lookback window = 7d)
quantile_over_time(0.95,
  rate(container_cpu_usage_seconds_total{
    namespace=~".+", container!="POD", container!=""
  }[5m])[7d:5m]
) * 1000  -- convert to millicores

-- Memory P95 per container
quantile_over_time(0.95,
  container_memory_working_set_bytes{
    namespace=~".+", container!="POD", container!=""
  }[7d:5m]
)
🔁Retry & Failure Handling
⏱️ Prometheus Ping Timeout
10-second hard timeout on cluster ping during registration. Cluster saved with status: disconnected — no data loss, retried on next scheduler run.
🔄 Background Goroutine Timeout
10-minute context timeout on the async goroutine spawned post-registration. If Prometheus is slow, this prevents goroutine leak.
📅 Scheduler Recovery
24h ticker is non-blocking. If a cluster's goroutine panics, it's recovered and the cluster's status is set to disconnected. Other clusters continue unaffected.
🗂️ Migration Dirty State
If a migration was interrupted mid-run, SyncSchema() detects the dirty flag and auto-retries from the last clean checkpoint.

13 Security

Security Model

🔑 JWT Authentication
HS256 signed tokens. Validated on every route via Gin middleware. user_id injected into context — never trusted from request body.
🔒 Token Encryption
Prometheus tokens encrypted with AES-256-GCM before INSERT. Tagged json:"-" — never serialized to API responses. Decrypted only in-memory during Prometheus calls.
🚫 SQL Injection
All queries use pgx parameterized statements. Zero string interpolation in SQL. No raw query builder.
🌐 Network
DB connection via sslmode=require in production. Prometheus calls over HTTPS. Internal K8s service mesh for inter-service comms.
14 Scalability & Performance

Performance Design

🏊Connection Pool Tuning
📏
Sizing guide: Set MaxConns to min(PostgreSQL max_connections / replicas, concurrent_goroutines × 2). Current default of 10 handles up to 100 clusters without pool exhaustion.
⚡Concurrency Model
📊 Scheduler Concurrency
One goroutine per cluster during sync. Bounded by a semaphore (default: 10 concurrent Prometheus scrapes). Prevents overwhelming Prometheus under high cluster count.
🔷 HTTP Concurrency
Gin handles concurrent requests via Go's goroutine-per-request model. Each request draws from the shared pgx pool. No global locks in any handler.
📈 Horizontal Scaling
Stateless API — scale replicas freely. Scheduler runs on all replicas — use a distributed lock (Redis or DB advisory lock) if you need exactly-once scheduling at scale.
🗃️ DB Bottleneck
Single PostgreSQL — current bottleneck at ~1000 clusters. Read replicas for ListClusters/ListRecommendations, primary for writes. Add index on recommendations(cluster_id, potential_savings).
15 Troubleshooting

Runbook

Common failures, diagnostic commands, and recovery procedures.

🔴 Cluster stuck in disconnected
Symptom: last_synced_at is null or very old. Recommendations not generating.
Check:
$ curl -s https://your-prometheus/api/v1/query?query=up
$ kubectl exec -it podoptix-pod -- curl http://prometheus:9090/api/v1/query?query=up
Fix: Verify Prometheus URL, token, and network reachability from the pod. Use PUT /clusters/:id to update the token, which triggers a re-ping.
🔴 migration dirty state on startup
Symptom: Server exits immediately with "dirty database version" log.
Fix:
$ psql $DATABASE_URL -c "UPDATE schema_migrations SET dirty=false WHERE version=1;"
Then restart. The migration will re-run from the last clean state.
🟡 /readyz returns 503
Symptom: Kubernetes marks pod as not ready. Traffic not routed to it.
Diagnose:
$ kubectl exec -it podoptix-pod -- curl localhost:8080/readyz
$ kubectl logs podoptix-pod | grep "ping db"
Cause: PostgreSQL unreachable. Check pod network policy, DB credentials, and PostgreSQL pod status.
🟡 No recommendations after sync
Symptom: Cluster is connected, last_synced_at is recent, but recommendations array is empty.
Diagnose: The Prometheus range query returned no data. Check:
$ curl "http://prometheus/api/v1/query_range?query=container_cpu_usage_seconds_total&start=...&end=...&step=5m"
Ensure the cluster has workloads running and Prometheus has at least 1 lookback window of data.

$ kubectl get pods -l app=podoptix -o wide

➕Adding a New Entity (Pattern)
📐
Follow this exact order to stay consistent with the codebase pattern.
1Write migrations/00000N_create_{entity}.up.sql and corresponding .down.sql
2Add struct to pkg/models/{entity}.go with json tags and constants
3Implement internal/store/{entity}.go with typed SQL functions
4Write internal/api/{entity}.go handlers — delegate only to store, no SQL here
5Register routes in internal/api/router.go
6Add integration tests in internal/store/{entity}_test.go
📏Code Conventions
Error wrapping
Always use fmt.Errorf("context: %w", err). Never swallow errors.
Context propagation
Pass ctx context.Context as first arg to every store function. Never use context.Background() in handlers.
No global state
All dependencies injected via struct. No package-level vars except constants.
json:"-" for secrets
Any field that must not appear in API responses gets json:"-". Test with a json.Marshal snapshot test.
